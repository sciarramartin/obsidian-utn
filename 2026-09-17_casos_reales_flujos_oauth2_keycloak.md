## 🎯 Objetivo de la Tarea

Asignar a cada flujo de la matriz de OAuth 2.0 / OIDC un **caso de uso real y cotidiano**, con explicaciones sencillas y comprensibles de cada escenario, del flujo elegido, del significado de los flags en Keycloak y de cómo funciona en la práctica.

---

## 📊 Matriz Comparativa Completa

| Escenario *(¿Qué significa?)* | Flujo y Tipo de Cliente *(¿Cómo funciona y qué es?)* | Flags en Keycloak *(¿Qué significa ON/OFF?)* | Ejemplo Cotidiano y Funcionamiento del Flujo |
| :--- | :--- | :--- | :--- |
| **1. SPA (Single Page Application)**<br><br>Una aplicación web moderna (React, Angular, Vue) que corre 100% en el navegador del usuario. No tiene un servidor propio intermedio para ocultar cosas. | **Authorization Code + PKCE**<br><br>**Cliente Público:** Corre en la máquina del usuario, por lo que cualquiera puede ver el código fuente con F12; no puede ocultar secretos. Usa un secreto efímero generado en memoria para verificar al cliente. | • **`Client auth: OFF`** $\rightarrow$ No genera clave secreta fija (`client_secret`) porque el navegador la expondría.<br>• **`Standard flow: ON`** $\rightarrow$ Habilita el login con redirección segura y exige el desafío PKCE (`code_challenge`).<br>• **`Direct access: OFF`** $\rightarrow$ Prohíbe mandar contraseñas en texto plano. | **VS Code en la Web (`vscode.dev`) con GitHub**<br><br>La SPA genera en memoria un verificador temporal (`code_verifier`) y calcula su hash (`code_challenge`). Redirige el navegador a GitHub para el login. GitHub devuelve un `code` en la URL. La SPA hace un `POST /token` enviando ese `code` + `code_verifier`. GitHub valida el hash y entrega los tokens sin haber necesitado una clave fija. |
| **2. Web Server-Side Tradicional**<br><br>Aplicación que corre en un servidor privado propio (Node.js, Java Spring, .NET, Python). Al ser un servidor cerrado bajo llave en la nube, puede custodiar secretos de forma segura. | **Authorization Code + PKCE con Secreto**<br><br>**Cliente Confidencial:** El backend corre en un entorno seguro y puede guardar un `client_secret` corporativo que los usuarios jamás ven. Combina el login del usuario con la identidad del servidor. | • **`Client auth: ON`** $\rightarrow$ Keycloak genera un `client_secret` que el backend guarda en sus variables de entorno privadas.<br>• **`Standard flow: ON`** $\rightarrow$ Redirige al usuario al navegador para que inicie sesión en el IdP.<br>• **`Direct access: OFF`** $\rightarrow$ El backend no pide ni almacena la clave del usuario. | **Tiendanube conectando cobros con Mercado Pago**<br><br>En el panel web de Tiendanube hacés clic en *"Conectar Mercado Pago"*. Tiendanube te redirige a la web de Mercado Pago para que autorices los permisos. Mercado Pago devuelve un `code` al servidor backend de Tiendanube. El servidor de Tiendanube (en sus servidores privados de AWS, fuera de la vista del navegador) canjea el `code` enviando su `client_secret` por un canal privado para obtener los tokens y poder cobrar en tu nombre. |
| **3. App Móvil Nativa**<br><br>Aplicación instalada en un smartphone (Android / iOS). Aunque esté compilada como APK/IPA, cualquier persona con herramientas básicas puede descompilarla y leer lo que tenga adentro. | **Authorization Code + PKCE (Navegador del sistema)**<br><br>**Cliente Público:** No puede guardar secretos fijos. En vez de pedir la clave en una ventanita casera adentro de la app (WebView inseguro), delega abriendo una pestaña segura de Chrome/Safari. | • **`Client auth: OFF`** $\rightarrow$ Sin clave secreta en la app (si existiera, la robarían descompilando la APK).<br>• **`Standard flow: ON`** $\rightarrow$ Delega la autenticación abriendo el navegador del sistema (*Custom Tabs*).<br>• **`Direct access: OFF`** $\rightarrow$ Prohíbe pedir usuario y clave en formularios embebidos dentro de la app. | **Duolingo en el celular (Android / iOS)**<br><br>Al tocar *"Iniciar sesión con Google"* en Duolingo, la app genera el par PKCE y abre una pestaña de Chrome/Safari del sistema. Como el navegador del celular ya tiene tu sesión de Google guardada con huella digital, confirmás en 1 toque. El navegador le devuelve el `code` a la app mediante un enlace interno del celular (`duolingo://oauth-callback?code=...`) y Duolingo lo canjea por tokens usando su verificador. |
| **4. Sistema a Sistema (M2M / Microservicios)**<br><br>Comunicación directa entre dos servidores, tareas programadas nocturnas o microservicios donde **no hay ninguna persona física sentada frente a una pantalla**. | **Client Credentials Grant**<br><br>**Cliente Confidencial:** La máquina que llama tiene su propio servidor seguro y se identifica a sí misma con credenciales de máquina. No hay identidad humana, solo permisos técnicos. | • **`Client auth: ON`** $\rightarrow$ El servicio se autentica usando su propio `client_id` y `client_secret` de máquina.<br>• **`Standard flow: OFF`** $\rightarrow$ No hay pantalla ni usuario humano interactivo para redirigir.<br>• **`Service accounts: ON`** $\rightarrow$ Habilita que el cliente actúe como una cuenta técnica autónoma con roles asignados en Keycloak. | **Bot de Discord (música/moderación) o GitHub Actions**<br><br>El bot de Discord es un script de Node.js que corre solo en un servidor a las 3 de la mañana. Para conectarse, hace una llamada directa `POST /token` enviando `grant_type=client_credentials`, su `client_id` y su `client_secret` (Token del Bot). Discord comprueba que las credenciales de máquina sean válidas y le entrega un token técnico con permisos (`bot`, `enviar_mensajes`), sin intervención humana. |
| **5. Dispositivo Entrada Limitada o Sin Navegador**<br><br>Aparatos como terminales de texto (consolas de comandos), Smart TVs, consolas de videojuegos o equipos IoT donde tipear con un teclado es imposible, engorroso o inseguro. | **Device Authorization Grant (RFC 8628)**<br><br>**Cliente Público o Confidencial:** La autenticación se divide en dos: el aparato muestra un código corto y el usuario hace el login real desde su celular o computadora más cómoda. | • **`Device Grant: ON`** $\rightarrow$ Habilita la emisión de pares de códigos (`device_code` y `user_code`) y el endpoint de sondeo (`/token`).<br>• **`Standard flow: OFF`** $\rightarrow$ El aparato no abre navegador propio.<br>• **`Direct access: OFF`** $\rightarrow$ Evita escribir contraseñas en consolas o con controles remotos. | **GitHub CLI (`gh auth login`) en la Terminal de Windows**<br><br>En la consola de comandos (PowerShell) no hay navegador web. Al ejecutar `gh auth login`, la terminal pide un código a GitHub y muestra en texto: *"Entrá a github.com/login/device e ingresá el código: 1234-5678"*. La terminal se queda haciendo preguntas periódicas (*polling*) con un `device_code`. Vos abrís tu celular o PC, ponés el código y aprobás. En el siguiente sondeo, GitHub le da el token a la terminal y queda logueada sola. |
| **6. Aplicación Heredada (Legacy First-Party)**<br><br>Sistemas antiguos de la propia empresa programados hace muchos años que piden usuario y clave en cajitas de texto y no saben cómo abrir navegadores web modernos. | **Password Grant (ROPC)**<br><br>**Cliente Controlado:** Solo aceptable transitoriamente en software propio mientras se migra a estándares nuevos. La app captura las contraseñas de las personas y las envía en texto plano. | • **`Direct access: ON`** $\rightarrow$ Permite enviar usuario y contraseña directamente en el cuerpo de la petición `POST /token`.<br>• **`Standard flow: OFF`** $\rightarrow$ No implementa redirecciones web modernas.<br>• **`Deprecado:`** Prohibido en desarrollos nuevos por el estándar OAuth 2.1. | **Aplicativos de escritorio viejos de AFIP (SIAP) o sistemas de facturación de cajas de Coto/Farmacity**<br><br>El software viejo de escritorio abre una ventana gris de Windows con dos cajas de texto: *"CUIT / Usuario"* y *"Clave Fiscal / Contraseña"*. El cajero escribe su clave y el software la manda por `POST` directo al servidor. Funciona, pero la app tuvo acceso a la clave en memoria, lo que **hace imposible usar biometría, llaves de seguridad o doble factor (MFA)** hasta que la empresa migre el sistema a abrir el navegador con PKCE. |
